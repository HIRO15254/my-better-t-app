# Feature Specification: モバイル基本レイアウト（Mobile Shell）

**Feature Branch**: `001-mobile-shell`
**Created**: 2026-03-12
**Status**: Draft
**Issue**: #1 - モバイルにおける基本レイアウトの構成

## User Scenarios & Testing *(mandatory)*

### User Story 1 - モバイル画面で等間隔配置のナビゲーションが表示される (Priority: P1)

モバイル端末でアプリにアクセスしたユーザーが、画面下部に5個のアイコンが等間隔に配置されたナビゲーションバーを見つけ、タップして各主要セクションへ移動できる。ナビゲーション項目は画面幅に対して均等に配分され、どの端末サイズでも一貫した間隔で表示される。

**Why this priority**: ナビゲーションはモバイル体験の根幹であり、これなしに他のどの機能も利用できない。等間隔配置はタッチ操作のしやすさに直結するため、MVP として最初に動作する必要がある。

**Independent Test**: モバイルサイズのビューポートでアプリを開き、画面下部にナビゲーションバーが5項目で等間隔に表示され、各アイコンをタップするとページ遷移が起きることを確認することで独立してテスト可能。

**Acceptance Scenarios**:

1. **Given** モバイル端末（またはモバイルサイズのブラウザ）でアプリを開いた状態で、**When** 画面が描画されたとき、**Then** 画面下部に5個のアイコンと対応するラベルを持つナビゲーションバーが表示され、各項目が画面幅を均等に分割して配置されている
2. **Given** ナビゲーションバーが表示されている状態で、**When** いずれかのナビゲーション項目をタップしたとき、**Then** 対応するページへ遷移し、タップした項目がアクティブ状態（選択中）として視覚的に区別される
3. **Given** あるページが表示されている状態で、**When** 別のナビゲーション項目をタップしたとき、**Then** 現在のページから新しいページへ切り替わり、ナビゲーションバーのアクティブ項目も更新される
4. **Given** 異なる画面幅のモバイル端末（小型スマートフォン〜大型スマートフォン）でアプリを開いた状態で、**When** ナビゲーションバーが描画されたとき、**Then** 5個の項目は画面幅に応じて均等にスペースを分配し、偏りなく配置されている

---

### User Story 2 - ヘッダーナビゲーションが削除され、全機能がボトムナビゲーションに統合されている (Priority: P2)

モバイルユーザーが、従来のヘッダーナビゲーションに代わり、画面下部のボトムナビゲーションからアプリの全主要機能にアクセスできる。ヘッダーナビゲーションは削除され、モバイル画面ではボトムナビゲーションが唯一のグローバルナビゲーションとなる。

**Why this priority**: ヘッダーナビゲーションの削除とボトムナビゲーションへの統合は、モバイルUXの一貫性を確保するために必須。ヘッダーとボトムの両方にナビゲーションがあると混乱の原因となる。

**Independent Test**: モバイルサイズのビューポートでアプリを開き、ヘッダーにナビゲーション要素が存在しないこと、かつボトムナビゲーションから全ての主要機能ページにアクセスできることを確認することで独立してテスト可能。

**Acceptance Scenarios**:

1. **Given** モバイル端末でアプリを開いた状態で、**When** 画面が描画されたとき、**Then** 画面上部にグローバルナビゲーション用のヘッダーバーは表示されない
2. **Given** ボトムナビゲーションが表示されている状態で、**When** ナビゲーション項目を順番にタップしたとき、**Then** アプリが提供する全ての主要機能ページに到達できる（従来ヘッダーナビゲーションにあった機能を含む）
3. **Given** デスクトップサイズのビューポートでアプリを開いた状態で、**When** 画面が描画されたとき、**Then** デスクトップ向けのナビゲーションは引き続き利用可能であり、モバイル用ボトムナビゲーションは表示されない

---

### User Story 3 - アプリ全体のテーマと一貫したナビゲーションスタイル (Priority: P3)

モバイルユーザーが、アプリの既存デザインテーマ（shadcn/ui）と統一されたスタイルのナビゲーションバーを利用でき、視覚的な違和感なくアプリを操作できる。配色、フォント、コントラスト、角丸、スペーシングなどがアプリ全体と調和している。

**Why this priority**: デザインの一貫性はアプリの信頼性と品質感に直結するが、ナビゲーション機能自体（P1/P2）が先決。

**Independent Test**: ナビゲーションバーの背景色・文字色・アイコン色・ボーダーがアプリの他のUI要素（ヘッダー、ボタン、カード等）と視覚的に調和していることをデザインレビューで確認することで独立してテスト可能。

**Acceptance Scenarios**:

1. **Given** ナビゲーションバーが表示されている状態で、**When** ユーザーがアプリ全体を閲覧したとき、**Then** ナビゲーションバーの配色・フォント・コントラストがアプリ全体のデザインテーマと一貫している
2. **Given** ダークモード/ライトモードが切り替え可能なアプリで、**When** テーマを切り替えたとき、**Then** ナビゲーションバーもテーマに追従して配色が変化する
3. **Given** ナビゲーション項目が表示されている状態で、**When** いずれかの項目がアクティブ状態のとき、**Then** アクティブ項目のスタイルがアプリのデザインテーマに定義された強調色を使用している

---

### User Story 4 - 開発者ツールとの干渉がない表示 (Priority: P4)

開発者が開発環境でアプリを使用する際、ルーティングやデータフェッチのデバッグツール表示がナビゲーションバーと重なったり干渉したりせず、両方の要素を同時に利用できる。

**Why this priority**: 開発効率に影響するが、エンドユーザー向けの機能（P1〜P3）より優先度は低い。ただし開発ワークフローを阻害しないために必要。

**Independent Test**: 開発環境でアプリを開き、デバッグツールのパネルとナビゲーションバーが視覚的に重複しないこと、かつ両方がクリック可能であることを確認することで独立してテスト可能。

**Acceptance Scenarios**:

1. **Given** 開発環境でモバイルサイズのビューポートでアプリを開いた状態で、**When** デバッグツール表示が有効化されているとき、**Then** ナビゲーションバーとデバッグツール表示が重なり合わず、両方の要素が操作可能である
2. **Given** 開発環境でナビゲーションバーとデバッグツールが同時に表示されている状態で、**When** ナビゲーション項目をタップしたとき、**Then** デバッグツールに遮られることなくページ遷移が正常に行われる
3. **Given** 開発環境でナビゲーションバーとデバッグツールが同時に表示されている状態で、**When** デバッグツールの操作を行ったとき、**Then** ナビゲーションバーに遮られることなくデバッグ操作が正常に行われる

---

### Edge Cases

- モバイルとデスクトップの境界となる画面幅（タブレットサイズ）でどちらのナビゲーションが表示されるか？
- ナビゲーション遷移中にページ読み込みが遅延した場合、ナビゲーションバーはどう振る舞うか？
- ブラウザの戻るボタンを使用した場合、ナビゲーションバーのアクティブ状態はURLと一致して更新されるか？
- 5個の項目ラベルが長い場合（多言語対応）、ナビゲーションバーのレイアウトが崩れないか？
- デバイスを横向き（ランドスケープ）に回転した場合、ナビゲーションバーはどのように表示されるか？
- 開発環境でデバッグツールの表示サイズが大きくなった場合、コンテンツ領域の使用可能な面積が極端に狭くならないか？
- ヘッダーナビゲーション削除後、ブックマークされた旧ナビゲーション経由のURLへアクセスした場合、適切なページが表示されるか？

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムはアクセス端末のビューポート幅に基づいてモバイルとデスクトップを判定し、それぞれ異なるナビゲーション表示を行わなければならない
- **FR-002**: モバイルと判定されたビューポートでは、画面下部に固定されたナビゲーションバーを表示しなければならない
- **FR-003**: ナビゲーションバーには正確に5個のナビゲーション項目を表示し、各項目は画面幅を均等に分割して配置されなければならない
- **FR-004**: 各ナビゲーション項目は Tabler Icons セットのアイコンとテキストラベルで構成されなければならない
- **FR-005**: ユーザーはナビゲーション項目をタップすることで対応するページへ遷移できなければならない
- **FR-006**: 現在表示中のページに対応するナビゲーション項目は、他の項目と視覚的に区別されるアクティブ状態で表示されなければならない
- **FR-007**: ナビゲーションバーはページコンテンツの上に重なって固定表示され、スクロールに追従しなければならない
- **FR-008**: デスクトップと判定されたビューポートでは、モバイル用ナビゲーションバーを表示してはならない
- **FR-009**: アクティブ状態の検出はURLパスと同期し、ブラウザの前後ナビゲーションにも対応しなければならない
- **FR-010**: モバイルビューポートにおいて、ヘッダーにグローバルナビゲーション要素を表示してはならない（ヘッダーナビゲーションを削除する）
- **FR-011**: 従来ヘッダーナビゲーションで提供していた全ての主要機能へのアクセスは、ボトムナビゲーションの5項目を通じて提供されなければならない
- **FR-012**: ナビゲーションバーのスタイル（配色、フォント、コントラスト、スペーシング）はアプリ全体のデザインテーマと一貫していなければならない
- **FR-013**: ダークモード/ライトモードの切り替えに対してナビゲーションバーのスタイルが追従しなければならない
- **FR-014**: 開発環境において、デバッグツール表示とナビゲーションバーが視覚的に重なり合わず、両方の要素が操作可能でなければならない

### Key Entities

- **Navigation Item**: ナビゲーション1項目を表す。属性: アイコン識別子（Tabler Icons）、表示ラベル、遷移先パス、アクティブ判定条件
- **Mobile Shell**: モバイルレイアウト全体のコンテナ。属性: 現在のナビゲーション項目リスト、アクティブ項目、ビューポート判定結果、テーマ状態

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: モバイルサイズのビューポート（幅767px以下と想定）では、全ページで画面下部にナビゲーションバーが表示される
- **SC-002**: デスクトップサイズのビューポート（幅768px以上と想定）では、モバイル用ナビゲーションバーが一切表示されない
- **SC-003**: 5個のナビゲーション項目全てにタップしてページ遷移が発生することを確認できる
- **SC-004**: ナビゲーション項目のタップから画面遷移完了まで体感的なラグがなく、ユーザーが遷移の開始を即座に認識できる（アクティブ状態の更新が瞬時に行われる）
- **SC-005**: ブラウザの前後ナビゲーションを使用した場合も、ナビゲーションバーのアクティブ状態が現在のURLと常に一致している
- **SC-006**: ナビゲーションバーの5項目が画面幅に対して等間隔で配置され、各項目のタップ領域が均等に確保されている
- **SC-007**: モバイルビューポートにおいて、ヘッダーにグローバルナビゲーション要素が表示されていない
- **SC-008**: 従来ヘッダーナビゲーションで提供していた全機能にボトムナビゲーションからアクセスできる
- **SC-009**: ナビゲーションバーのデザイン（色、フォント、アイコンスタイル）がアプリの他のUI要素と視覚的に一貫している
- **SC-010**: 開発環境でデバッグツールとナビゲーションバーが同時に表示された際、両方の要素が重なり合わず操作可能である

## Assumptions

- モバイル判定の閾値は幅767px以下とする（一般的なスマートフォン最大幅に基づく推定）
- タブレット（768px〜1023px）はデスクトップ扱いとする（要件に明記がないため保守的に判定）
- 5個のナビゲーション項目は、従来ヘッダーナビゲーションで提供していた機能を網羅するように構成される（具体的な項目名は実装時に確定）
- ランドスケープ（横向き）モードでもモバイル端末であればナビゲーションバーを表示する
- ナビゲーションバーはスクロール位置に関わらず画面下部に固定表示する
- 開発環境のデバッグツールとの干渉回避は、ナビゲーションバーのz-indexやポジショニングを適切に設定することで対応する（デバッグツール側の変更は不要と想定）
- アプリのデザインテーマはshadcn/uiのテーマトークン（色、スペーシング、タイポグラフィ）に準拠しており、ナビゲーションバーもそれらを使用する

## Out of Scope

- デスクトップ向けナビゲーション（サイドバー、トップバー等）の変更・再設計
- ナビゲーション項目の動的な追加・削除・カスタマイズ機能
- ナビゲーション項目のバッジ（通知数）表示
- アニメーション・トランジション効果の詳細仕様
- ユーザー認証状態によるナビゲーション項目の出し分け
